Writing LaTeX
How I write my LaTeX code.

These are my thoughts and opinions on writing LaTeX code. Of course, this is just my way of doing things, I do not claim that this is the best way of doing things.

The Setup

In general, my philosophy for setting up and writing LaTeX prioritizes the following three things in decreasing order of importance:

  1. Convenience, ease of use, and laziness
  2. Aesthetic quality of the result
  3. Cleanliness and organization of the code

After a long time, I have decided that the best way to accomplish this is with the following structure:

Preamble
documentclass:
PSet
Paper
Report

I believe this is the standard way to do things, but nonetheless, I have met a surprising number of people who are unfamiliar with this methodology. Essentially, I put stuff in my preamble that I want to include in all my tex files. This includes things like math commands, some packages, and the way I like the enumerate environment to act.

In each .cls file I import the preamble via the \input{} command. I have different document classes defined for different purposes. The document class contains all the specific stuff, like theorem environments, code for how the title and bibliography should look, etc. Then, using the document class is as simple as putting it in the \documentclass{} command.

This avoids having long and identical preambles at the start of everything I write, and means that any change will propagate through everything I do later.

In terms of the actual aesthetics, my taste is generally quite conservative for subjects like physics and math, and less so for things such as chemistry or biology. Perhaps this is because in mathematics, one needs to devote all their brainpower to reasoning through the mathematics, so clutter on the page is just distracting. On the other hand, biology and chemistry can be quite nonlinear, and can get so confusing and complicated that having colors or boxes as visual guides is often necessary in order to not get lost. This is all just speculation though.

The Writing

One of the most important personal choices in how you write latex code is the code editor. I would conjecture the most popular options are:

  1. Overleaf
  2. Visual Studio Code
  3. Vim or Neovim
  4. Texmaker or some other dedicated software

I would claim that Visual Studio Code or Neovim are the best options. They both have the advantage of customizability, a vibrant plugin system, offline use, and highly optimized shortcuts. More broadly, they are capable and customizable code editors. People have spent years and countless hours perfecting the process of writing code, and writing LaTeX is quite similar to writing code, so it makes sense to use a code editor. I also write a lot of code, so it makes sense to use the same software for both tasks.

I personally use Neovim, which I learned around freshman year and after a period of getting used to it I find it gives a nice coding experience. I am by no means a neovim wizard, however I know all the basic keybinds needed to get the job done. I would conjecture that it makes writing text feel a bit smoother and more subconscious. For instance, physics has a lot of integrals which are a pain to write out like \int_{-\infty}^\infty f \, dx. However due to LuaSnip, if I type intinf ENTER f TAB x then I'm done since I have a shortcut for these integrals. There is a much more direct line from by brain to the text than if I didn't have these shortcuts (it is worth noting VSCode has equivalent functionality to this). These days I use LazyVim, which is quite customizable but at the same time gives a very nice premade setup and reduces maintenance load.
