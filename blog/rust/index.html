My Opinion on Rust
My personal feelings about the most beloved programming language.

I attempted to learn Rust, which some hail as a C replacement. Overall, Rust is a fantastic programming language, with lots of great design choices. It is very good at certain tasks, but I can't quite view it as a C replacement.

Pros

Rust makes a lot of good decisions which I think other languages should learn from. The borrow checker is a novel and brilliant idea. Furthermore, the syntax is modernized (I love the type names) and extremely logical (the idea of every scope returning a value is brilliant). Don't even get me started on cargo, it is probably the best build system/package manager I have ever used.

The biggest plus is obviously the novel combination of memory safety and speed. These factors make Rust the best language (in my opinion) for use cases which demand extreme performance and reliability, without requiring too many complicated data structures.

It is clear that Rust is a language in which you declare a lot of intent to the compiler. This can sometimes be a con, as I talk about below. However perhaps it may also become a pro. My hope is that eventually Rust code will be optimized more aggressively than C. For instance, in C, very few are willing to go around putting the restrict keyword everywhere they can. Rust on the other hand sort of forces you to tell the compiler these things, and therefore may allow for more aggressive optimization once compilers adapt to Rust. This is all just speculation through.

Cons

At this point I would like to challenge the reader to implement a doubly linked list or a binary tree in Rust without looking at a guide. This is an intuitive task in C, just draw something on a blackboard and set up all the pointers how you would expect. In Rust it is a pain, there is no way around it. I might have a skill issue, but I find the experience of coding in Rust to be similar to coding in C, except you have an imp on your shoulder (the borrow checker) who won't let you run your code until you convince them that it will work. Rust has bunch of different kinds of objects (Box, Rc, Cell, etc), it turns out they are all pointers but you are only allowed to use each one in a very specific way.

Personally, I would sometimes rather that my compiler just trusted me and ran the code without me needing to convince it that I know what I'm doing. This inevitably leads to memory leaks, segmentation faults, and data corruption, however I can catch this stuff quite well with valgrind. Furthermore, I am a big fan of simplicity, and having a single framework (pointers) which can be extended to accomplish any task is very nice on a moral level. The excessive number of different pointer types Rust has on the other hand is not aesthetically pleasing. However I can understand why it is necessary and I still find Rust to be a fantastic language. I can't wait to see where it goes.
